# CART-TRACE Governed Execution Decision Plan

## Purpose

This document defines the decision immediately following Gate 6 methodological readiness. It prevents the public repository from conflating protocol readiness with institutional authorization or actual governed-data availability.

## Branch A — Governed execution

Proceed only if the responsible institutional team has documented, inside the approved environment:

- required approvals and data-use authorization;
- approved users and governed environment;
- actual source-field availability;
- a reviewed local mapping version;
- a validation/adjudication sample plan;
- permitted output/disclosure rules;
- a completed pre-analysis checklist with no unresolved frozen-method violation.

### First governed work products

1. source-field availability matrix completed from `source_field_inventory.md`;
2. data-quality profile completed from `data_quality_profile_template.md`;
3. local mapping table with review status and version;
4. reconstructability worksheet for the governed cohort;
5. follow-up sufficiency characterization;
6. discrepancy log initiated before adjudication;
7. source-concordance validation sample defined;
8. public-release review for any proposed aggregate output.

### First governed analyses

The first analyses should be descriptive readiness/representation analyses rather than hypothesis-generating expansion:

- cohort and infusion-anchor accounting;
- mapping coverage;
- reconstructability distribution;
- unknown/uncertainty burden;
- timestamp and overlap/conflict profile;
- metric availability and follow-up sufficiency;
- source-concordance agreement and discrepancy classes.

Only after those results are reviewed should the frozen trajectory and utilization summaries be treated as the primary governed descriptive analysis.

## Branch B — Scholarly synthesis

Use this branch if approvals/access are unavailable, delayed, or outside the capstone timeline.

The capstone remains methodologically complete through Gate 6. Work should then prioritize:

1. finalize Methods from the frozen specification and governance package;
2. finalize synthetic Results without overstating external validity;
3. write Discussion around representation validity, uncertainty, governance transfer, and limitations;
4. document that governed application was prespecified but approval/access dependent;
5. complete reproducibility and public/private-boundary statements;
6. prepare final figures/tables, presentation, and repository release package.

Lack of governed data should be reported as a study limitation and implementation constraint, not addressed by broadening the software or adding unsupported clinical claims.

## Frozen-method stop rule

Regardless of branch, any proposed change to canonical states, transition semantics, `[start,end)` behavior, source precedence, metric definitions, follow-up interpretation, or synthetic oracle expectations requires explicit gate-impact review. It is not a routine local adaptation.

## Decision record

When the project moves beyond Gate 6, record the selected branch as one of:

- `governed_execution_authorized`;
- `governed_execution_pending`;
- `scholarly_synthesis_due_to_access_constraint`.

The record should state the date, responsible decision context, and whether any institutional information must remain outside the public repository.
